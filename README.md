# SpringDating API 💘

Бэкенд для сервиса знакомств, написанный на **Java 25** с использованием **Spring Boot 4**.
Проект реализует полный цикл взаимодействия пользователей: от регистрации и заполнения профиля до свайпов, создания мэтчей, обмена сообщениями в реальном времени и получения уведомлений.

## 🚀 Основные возможности

*   **Аутентификация и безопасность**: JWT (Access + Refresh), ротация Refresh-токенов, безопасное хранение токенов в `HttpOnly` cookies. Защита от брутфорса (Rate Limiting).
*   **Профили пользователей**: Гибкое редактирование (PATCH), валидация данных, проверка "заполненности" профиля для доступа к основному функционалу.
*   **Работа с медиа**: Загрузка до 5 фото на пользователя (валидация размера, MIME-типов). Интеграция с **MinIO** (S3-совместимое хранилище), генерация временных ссылок (Presigned URLs) для безопасного просмотра.
*   **Колода и Свайпы**: Формирование персональной колоды на основе предпочтений (возраст, пол, город). Умная обработка свайпов (лайки/дизлайки) с защитой от race conditions.
*   **Мэтчи**: Автоматическое создание взаимных мэтчей. Возможность отмены свайпа (с автоматическим удалением мэтча и чата).
*   **Чат в реальном времени**: Обмен сообщениями через **WebSocket (STOMP)**. Курсорная пагинация истории сообщений (защита от дублирования при активной переписке). Отметки о прочтении.
*   **Уведомления**: Асинхронная обработка событий (лайки, мэтчи, новые сообщения) через `@TransactionalEventListener`.
*   **Мониторинг**: Сбор метрик через Micrometer, интеграция с **Prometheus** и **Grafana**.

## 🛠 Технологический стек

*   **Язык**: Java 25
*   **Фреймворк**: Spring Boot 4 (WebMVC, Data JPA, Security, WebSocket, Actuator)
*   **База данных**: PostgreSQL 18 (+ Flyway для миграций)
*   **Кэширование и Rate Limiting**: Redis 7 (+ Bucket4j)
*   **Хранилище файлов**: MinIO
*   **Документация**: Springdoc OpenAPI (Swagger UI)
*   **Маппинг и Бойлерплейт**: MapStruct, Lombok
*   **Тестирование**: JUnit 5, Mockito, Testcontainers (PostgreSQL, Redis), Spring Boot Test
*   **Инфраструктура**: Docker, Docker Compose

## 🏗 Архитектура и особенности реализации

*   **Event-Driven подход**: Слабая связанность модулей через Spring Events (`LikeEvent`, `MatchCreatedEvent`, `ChatMessageEvent`). Уведомления и создание чатов реагируют на события *после* успешного коммита транзакции (`TransactionPhase.AFTER_COMMIT`), что исключает появление "фантомных" данных при откатах.
*   **Защита от Race Conditions**: Использование пессимистичных блокировок (`PESSIMISTIC_WRITE`) при работе с лимитами фото и обработкой дублирующихся свайпов.
*   **Кэширование**: Активное использование Redis для кэширования профилей, списков фото и проверок наличия главного фото. Грамотная инвалидация кэша через `@Caching`.
*   **Оптимизация запросов**: Использование проекций (Projections) в JPA для выборки только необходимых полей (например, имен пользователей) и предотвращения проблемы N+1.

# 🧪 Тестирование

Проект покрыт тестами всех уровней — от изолированных юнит-тестов до полных интеграционных сценариев с реальными PostgreSQL и Redis.

### Стек

**JUnit 5** · **Mockito** · **AssertJ** · **Spring Boot Test** · **MockMvcTester** · **Testcontainers** (PostgreSQL 16, Redis 7) · **RestTestClient** · **WebSocketStompClient**

### Уровни тестов

| Уровень | Аннотации | Что проверяет |
|---|---|---|
| **Юнит** | `@ExtendWith(MockitoExtension.class)` | Сервисы, мапперы, фильтры, JWT — все ветки логики с моками |
| **Контроллеры** | `@WebMvcTest` | HTTP-статусы, JSON-тело, cookie (`HttpOnly`, `Path`, `Max-Age`), валидация |
| **Репозитории** | `@DataJpaTest` + Testcontainers | Реальные SQL-запросы, ограничения БД, сортировки, курсорная пагинация |
| **Интеграционные** | `@SpringBootTest(RANDOM_PORT)` | Полные сценарии через HTTP и WebSocket с реальными БД, Redis, MinIO |

### Покрытие по модулям

- **Auth** — регистрация, логин, refresh-ротация, logout, JWT-фильтр, rate-limit (`429`)
- **User** — PATCH-валидация, `completeness`, готовность профиля, `getByPreferences`
- **Swipe / Match** — self-swipe, гонки (`DataIntegrityViolationException`), undo с удалением мэтча и комнаты
- **Chat** — STOMP-доставка, read-receipt, изоляция комнат, ошибки для не-участников
- **Photo** — лимиты размера/количества/MIME, cleanup MinIO при сбое БД, смена main-фото
- **Notification** — создание, ownership-проверки, отправка push, `markAllAsRead`
